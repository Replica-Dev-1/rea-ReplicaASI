Recorded sample and reviewed reconstruction. “Parent” and “descendant” name package versions here, not minted replicas. No installation or wallet is needed to try the result.

1. inspect

Question: how does this app search titles and note bodies, rank matches, and apply filters?

REA examined the source of our small, MIT-licensed notes app and recorded evidence about its search. The reconstruction below was prepared from that investigation and checked with separate tests. Replica's standalone specialist reuses this reviewed recipe and reruns the checks locally. This page is a working example; it does not run REA on your computer.

4. inherit, then extend
The descendant keeps the parent's search.js byte for byte and adds all-word matching and a result limit in child.js. Its package points to the exact parent package digest and includes fresh checks alongside the regression checks.




This example lets you try and download both package versions. To use them with a replica, connect its hosting wallet on the main page, review and save a package, allow inheritance, and invite another wallet. A descendant can keep the exact files and save an extension that points back to them.


This demonstrates tested code reuse. Replica's standalone search specialist can now rebuild this known example and extend a reviewed parent through Replica Runner. It uses an authored recipe for the exact reference source, with local approval and newly executed checks. No language model is involved in that runtime.
