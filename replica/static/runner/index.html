REA also runs directly on the main site. connect your hosting wallet, choose a sample or upload a source file under “investigate with REA”, and choose “run REA”. no installation is needed for website inspection. this guide covers the optional local runner and its build specialists.

your replica, working locally

choose a source file. your replica uses REA to inspect it, then checks whether one of its own specialists can build a useful result. the agents run locally, without a language model or an upstream agent connection.

download Replica Runner · read the complete setup and data-handling guide

1. install the tools

extract the download into a new folder. you need Python 3.10+ and a supported Node.js version; Node 24.22.1 was tested. open a terminal in that folder:

npm install --ignore-scripts --prefix integrations/rea
python tools/replica_runner.py doctor

this installs REA 6.8.0 locally. it does not inspect your files or connect a wallet.

2. pair with your replica

on the main page, connect the wallet hosting your replica. open “investigate with REA”, then “connect your computer”. create a pairing code and run:

python tools/replica_runner.py pair --site https://replicaasi.com --name "my computer"

paste the code into the terminal when asked. it works once and expires in ten minutes. keep it private.

3. choose one file

start with the included notes example, or replace its path with a JavaScript or TypeScript source file you own or have permission to inspect:

python tools/replica_runner.py serve --source "samples/notes-target/search.cjs" --label "notes example"

leave the terminal open. the site shows the selected file. ask “Build the notes search.” there and start the investigation. read the request in your terminal and type inspect to approve. REA reads an isolated copy of that one file; it does not run the inspected program.

4. let a specialist build and check

the agent checks the source and evidence against its capabilities. if a specialist covers the task, read its scope and type build. it assembles the supported implementation and runs its checks in a separate local folder. unsupported tasks are declined.

the first specialists cover simple arithmetic helpers and the included notes-search example. the search specialist uses an authored recipe for that exact source; it is not a general app builder. read the supported forms and limits.

5. review, save and pass it on

open the package path printed in your terminal. read its source, implementation, tests and evidence before typing send. every included file goes to your private review area. without a build package, only the displayed inspection summary and file identity are sent.

on the site, review the result again and choose whether to save it publicly and allow inheritance. a descendant receives the exact approved package. its owner can select that downloaded parent with --parent, then ask “Extend the notes search with all words and a limit.” the new package links back to its parent.

see the tested search example and its descendant.

give each agent a scope

the local agent profile lets you choose a name and enable a subset of the admitted specialists. each run records the profile and the replica's own identity. profiles cannot enable a language model, remote fallback or arbitrary commands.

what stays private

the automatic inspection summary excludes source text and absolute local paths. the question, chosen label, filename and summary are stored on the relay for private review. they are not end-to-end encrypted. original evidence stays local unless you deliberately include it in a later package.

source and evidence are not sent to a model provider. sending a build package shares its included files with Replica's private relay. publishing that package makes every included file public.

you can disconnect the runner from the site. a new wallet owner cannot use your computer connection or read your private jobs. no wallet secret key is given to the runner.
